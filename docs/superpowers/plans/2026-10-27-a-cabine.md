# A Cabine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone DDJ-FLX4 at `/cabine` inside dj-lab: two decks + mixer in FLX4 positions, rekordbox behavior, offline after "carry", mixes recorded and uploaded to O Arquivo.

**Architecture:** Server (FastAPI, `djlab/`) gains a beat-grid module (Beat This!), a cabine module that serves carry-ready MP3s, waveform peaks and grids, SoundCloud intake, and compressed exports. The client is a set of ES modules under `djlab/static/cabine/`: pure logic modules (grid math, deck transport, mixer math, control map) unit-tested with `node --test`, a custom AudioWorklet deck player (int16 PCM, any rate including negative), a Web Audio mixer with split cue, an IndexedDB store, and a DOM board driven by one declarative FLX4 control map. A service worker scoped to `/cabine` makes the shell work offline.

**Tech Stack:** Python 3.12, FastAPI, librosa, Beat This! (MIT), ffmpeg, yt-dlp, pytest; vanilla JS ES modules, Web Audio + AudioWorklet, IndexedDB, Service Worker, MediaRecorder; `node --test` (Node 22); Playwright (Python, host) for e2e.

**Spec:** `docs/superpowers/specs/2026-10-27-a-cabine-design.html` (approved 2026-10-27). Read it before any task. Its control map (section 5) is normative, subject to "the manual wins".

## Global Constraints

- Primary target: Samsung Galaxy S7, **Chrome 138 frozen** (no web API newer than Chrome 138), landscape **640 x 360** CSS px, 4 GB RAM. Second target: current iPhone Safari, landscape **844 x 390**.
- No build step, no npm dependencies in the shipped client. ES modules loaded directly. Node is for tests only.
- Board positions follow the real FLX4 top panel; behavior follows the DDJ-FLX4 rekordbox operating instructions; where the spec and the manual disagree, the manual wins and the spec's control map gets a note.
- Anti-goals are hard rules: no control placed or behaving differently from the FLX4; no phone-only shortcuts on the board (tap waveform, auto-sync on load, swipe gestures); nothing on the board touches the network once tracks are carried.
- Public repo: no PIN, PIN hash, tokens, or the friend's name in code, docs, tests or commits. Read secrets from `~/config/dj-lab.env` at test time only.
- `/static/` is public. Only non-secret code goes there. Audio and APIs stay under gated `/api/` routes.
- Do not change the existing mesa's behavior. New CSS lives in `djlab/static/cabine/cabine.css` with every selector under `.cab-` prefixes. Do not add code to `escola.js` except the O Arquivo extension fix in Task 4.
- Tracks over **900 s (15 min)** are refused at search (flagged) and at pull (error "that's a set, not a track").
- New pulls land in `sources/techno/`.
- Carried audio: MP3, libmp3lame `-q:a 0` (VBR V0), 44.1 kHz stereo, gapless LAME header kept.
- Beat FX v1 set, in FX SELECT order: Delay, Echo, Reverb, Flanger, Roll. Beat fractions: 1/4, 1/2, 3/4, 1, 2, 4.
- Tempo ranges, cycled by SHIFT + BEAT SYNC: ±6, ±10, ±16, WIDE (±100). Default ±10 unless the manual says otherwise. Slider down = faster.
- Drawn-only controls show the toast "not yet" for 1.2 s: Mic, Smart CFX, Smart Fader, PAD FX1, PAD FX2, KEYBOARD, KEY SHIFT, CUE/LOOP CALL with no loop active.
- Before any `docker compose up -d --build` or restart of `dj-lab`: `curl -s localhost:8127/api/jobs` (with cookie) and wait while any job has `status: running`.

## Review Focus

1. **Grid vs decoded audio offset.** MP3 encoder delay can shift the decoded audio against a grid computed from the WAV. Expected: the first grid beat lands within 5 ms of the first kick in the browser-decoded carried file. Test: Task 2 `test_carry_mp3_aligned_with_wav` + Task 5 e2e `test_carried_buffer_grid_alignment`.
2. **Loading a 15-minute track on a 4 GB phone while the other deck plays.** Expected: no audio dropout on the playing deck, no tab kill, memory released from the decode. Test: Task 5 e2e `test_load_while_playing_no_underrun` (counts worklet underruns) + Task 6 real-phone checkpoint.
3. **Multi-touch collisions.** SHIFT held on one deck while the other thumb works a pad or fader; a finger sliding off a control mid-drag. Expected: each pointer stays bound to the control it started on until lift; SHIFT is per deck. Test: Task 9 e2e `test_multitouch_shift_pad_and_fader` using CDP `Input.dispatchTouchEvent` with two touch points.
4. **Going offline mid-session and coming back with an expired cookie.** Expected: board keeps working; recordings queue; once online, uploads that get 401 stay queued and the crate shows "enter PIN", nothing is lost. Test: Task 11 e2e `test_upload_queue_survives_401`.
5. **Bad or missing grid.** Track with `beat_cv > 0.12`, grid job failed, or grid fixed while loaded. Expected: plays fine; SYNC and quantize disabled with the note "no reliable grid"; a grid fix while loaded takes effect on next load only. Test: Task 5 `deck_no_grid_disables_sync` + Task 8 e2e `test_grid_fix_roundtrip`.
